# 三平台机器人真人接管与文档处理参考

目标是让 AI 在员工授权的原办公会话中处理任务、整理文档，并用员工身份回复原私聊或群聊。企业微信、飞书、钉钉各自保留普通机器人通道，员工授权、文档授权和回复目标分别校验。

| 内容 | 用法 |
| --- | --- |
| [跨语言消息接管实现](说明/跨语言消息接管实现.md) | 按数据契约、状态机、事务和伪代码移植到任意技术栈 |
| [三平台接入与文档交付](说明/三平台接入与文档交付.md) | 查消息接口、授权、文档读写与交付 |
| [验证结果与复现步骤](验证/验证结果与复现步骤.md) | 按平台核对实测范围、历史回归和新环境验收用例 |
| [工程对照与配置](说明/工程对照与配置.md) | 找 Java、Node.js、SQL、技能和线协议对应位置 |
| [归档清单](MANIFEST.sha256) | 核对文件和 SHA-256 |

源码基于 servyou-work-external 的提交 e954af6ab 导出。配置工具基于同机独立项目，附样例应用配置。验证材料使用匿名结果、原测试日期和可复现步骤。三张汇报架构图和 Draw.io 源文件放在 **架构图** 目录。

**实施顺序** 先用本人授权跑通一个私聊和受控群的读取与文本回复，再接持久队列和重复回复检查。接入文档后，按同一文档 ID 做正文读回，再让接收者从聊天中打开链接。
