## 2. 原会话本人身份验证

1. 由员工使用自己的授权，选一个受控私聊和一个测试群。分别让测试对端发送带唯一编号的消息。记录原会话 ID、发送者标识、平台时间及正文摘要。
2. 在员工身份下查两处历史。核对目标、发送者与正文。企微和飞书已在四处指定会话各找到测试对端消息，统计为 4 个命中，查询阶段发送数为 0。
3. 当发送场景获授权时，各向原会话提交一次带唯一编号的文字。企微和飞书的群聊验证各有 5 项断言通过，包括目标群唯一、业务成功、本人标识、正文和群一致、只有一条匹配。钉钉使用本人私聊做发送与读回。
4. 第二个节点接管后的回查仍用同一个持久任务 ID。回执丢失时验证不会再次提交，使用外部消息 ID、任务回执或原会话历史核实。

## 5. 新项目验收用例

| 用例 | 预期结果 |
| --- | --- |
| 历史分页失败或服务重启 | 水位保留，完整窗口再合并，同条消息只生成一个任务 |
| 同时间、同正文的两条真实消息 | 具备稳定平台 ID 或稳定序号，各自保留 |
| 一群两个人被分别点名 | 只有匹配个人的任务触发。普通群消息和仅 @全体成员作为上下文 |
| 员工在模型执行中手动答复 | 发送前复查识别原会话的人工回复，阻止自动回复 |
| 模型运行中到达后续输入 | 原消息完成后，新增输入按新的水位继续处理 |
| 节点失去归属或员工撤权 | 旧节点进度、回执写入及之后的发送被拒绝 |
| 令牌续期请求超时 | 保留授权结果未知状态，按本人重新授权恢复 |
| 平台受理但发送回执超时 | 记 UNKNOWN。查原会话或异步任务，避免重复发出 |
| 文件或文档属于其他会话或租户 | 归属核验失败。模型对外返回具体业务结果 |
| 文档工具返回任务号 | 轮询任务直至正文可读，再用同一资源核验并回链 |
| 接收者打开文档链接 | 看到正确文档及正文。权限不足时记录到权限环节 |

[跨语言验收样例](跨语言验收样例.json) 提供可直接用于实现的合成群消息。依时间顺序输入，验证点名、两条同正文消息分别入站、员工手动回复后取消旧任务及重叠轮询去重。
