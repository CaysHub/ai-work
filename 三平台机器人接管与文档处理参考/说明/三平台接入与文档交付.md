# 三平台接入与文档交付

## 一、企业微信

### 机器人、个人消息和个人文档

| 通道 | 授权与实现 |
| --- | --- |
| BOT | 企业 ID、BotID 和 Secret 接入智能机器人 WebSocket。按 req_id 关联事件和回执，可在机器人会话内处理文本、流式回复和原生文件 |
| USER 消息 | 员工授权的 msg MCP，使用 messageUserId 识别本人，工作台绑定使用另一套回调 userid。私聊目标为对方在消息接口中的 userid，群聊目标为群 chat_id |
| USER 文档 | 员工授权的 doc MCP，覆盖该授权可访问的文档。文档授权与 msg 地址分开保存 |

同一个真实 BotID 在工作台只能启用一种 BOT/USER 身份。若已有其他身份在线，先关闭再启用目标配置。一个 msg/doc 授权对应确定的授权人和访问范围。员工之间需要独立配置和授权。

### 真人会话读写

1. 对已选会话调用 chat_messages_list。传入 chat_id、begin_time、end_time 及分页 cursor。北京时间格式为 YYYY-MM-DD HH:mm:ss。活跃群发现使用 chat_groups_list。新增私聊通过登记目标 userid 进入范围。平台历史查询最近 7 天，接管服务在积压超过 6 天时停下。
2. 解析 messages、userid、send_time、msg_type、text.content。只有成功码、明确计数为 0 及 has_more=false 同时成立时，允许数组缺失表示空页。媒体引用从类型对应字段取 media_id。通过 message_files_get 获取对应 Base64，验证大小并解码。
3. 使用 message_send，传 chat_id、msg_type=text 和 text.content，正文最多 2048 字符。检查工具内业务结果。平台可能不给消息 ID，用原会话历史核验本人、时间和正文。云文档成果以文本链接回原会话。BOT 模式的 message_aibot_send 和原生文件能力单独使用。

### 云文档读写

服务端校验官方 MCP 主机和能力路径，凭据保持在服务端。initialize 后分页 tools/list 获取当前工具定义，按 inputSchema 校验，再用 tools/call 调用。HTTP、JSON-RPC 及工具内部业务码都需成功。授权范围缩小时按最新目录执行。

| 阶段 | MCP 工具及关键参数 |
| --- | --- |
| 创建 | doc_create，doc_type=doc、doc_name、content。保存返回 docid 和平台 URL |
| 更新 | doc_contents_append 追加。doc_contents_overwrite 整篇覆写，确认目标与更新意图后调用。按目录提供 docid、content 和 content_type |
| 读取 | doc_contents_get_submit，传 docid、content_type。保存 taskid 并调用 doc_contents_get_query，直到完成并取得正文 |
| 交付 | 按同一 docid 读回关键段落，检查接收者权限，将平台真实链接回复原会话 |

配置清单可扩展 doc、msg、todo、schedule、meeting、disk、contact 七类。工具按能力和动作授权。工作台在 /im/bot/tool/page 暴露目录，在 /im/bot/tool/execute 执行工具。已有 /im/bot/document 接口保留兼容入口。按租户、机器人使用授权和会话文件归属校验。文档技能优先走后端持久发送接口交付。

## 二、飞书

### 机器人、员工消息与应用文档

| 通道 | 授权与实现 |
| --- | --- |
| BOT | App ID 和 App Secret 配合官方 SDK 长连接，订阅接收消息事件并启用机器人能力。工作台绑定使用当前应用的 open_id |
| USER 消息 | 飞书 OAuth user_access_token、refresh_token。本人须在应用权限发布后授权。以本人 open_id 核对绑定 |
| 文档 | 应用凭 App ID/App Secret 通过 OAuth v3 client_credentials 获取应用访问令牌。对应 API scope 和文档或文件夹资源权限均需具备 |

本人消息授权使用 im:message、im:message:readonly、im:message.p2p_msg:get_as_user、im:message.group_msg:get_as_user、im:message.send_as_user 和 offline_access，按平台接口开通。可选搜索加 search:message。已授权的旧 token 要重新授权才可取得新增 scope。

### 真人会话读写

1. 当前工作台使用 accounts.feishu.cn/open-apis/authen/v1/authorize，登记回调地址，绑定短期 state。服务端通过 accounts.feishu.cn/oauth/v3/token 用授权码换 token，再以 GET /open-apis/authen/v1/user_info 核对 open_id。受理回调时校验配置版本及登录人。
2. 已知会话使用 GET /open-apis/im/v1/messages，传 container_id_type=chat、container_id、start_time、end_time、sort_type=ByCreateTimeAsc、page_size=50，并沿 page_token 翻页。返回的 create_time 为毫秒，历史查询边界为秒。保存 message_id、sender.id、message_position 和 mentions。富文本正文按消息类型结构化解析。
3. 活跃会话发现用 POST /open-apis/im/v1/messages/search，空 query 和时间范围、用户消息来源过滤。用 meta_data.chat_id、is_p2p_chat 构建会话。搜索依赖索引，结果若含 notice 或无有效后续游标则报错或按末页语义处理。
4. 向原会话 POST /open-apis/im/v1/messages?receive_id_type=chat_id。正文为 receive_id、msg_type=text、字符串化的 content JSON 和请求 uuid。检查业务 code=0 和 data.message_id。本人附件按原消息 ID 和 file_key 调用消息资源接口，以本人令牌验证访问权限。

### 云文档读写和链接交付

| 阶段 | 应用 API 与结果 |
| --- | --- |
| 建文档 | POST /open-apis/docx/v1/documents，传 title，按需带 folder_token，记 document_id |
| Markdown 转块 | POST /open-apis/docx/v1/documents/blocks/convert，传 content_type=markdown 和 content |
| 写内容 | 平铺块走 blocks/{block_id}/children。保留嵌套结构时用 blocks/{block_id}/descendant，按转换结果传 children_id 与 descendants。处理 revision 冲突 |
| 读回 | GET /open-apis/docx/v1/documents/{document_id}/raw_content，校验正文。按需分页读取块列表核对层级 |
| 找链接 | 通过云空间文件查询取得该 document_id 的 URL，核对 token 和权限。向原会话发送链接，并在接收者客户端点开实际文档 |

普通文档应开通 docx:document 或所需细粒度权限。Markdown 转块单独开 docx:document.block:convert。云空间列表用 drive:drive 或足够的只读权限。电子表格、多维表格、知识库、导入导出按动作分别请求 scope。动作字段、路径白名单和 API 版本可查配置目录的 JSON 动作表。

## 三、钉钉

### Stream 与员工个人通道

普通机器人拿应用凭据建立 Stream，用机器人发消息时调用 robot/groupMessages/send 或 robot/oToMessages/batchSend。员工接管使用钉钉开发者平台「CLI 设置 → Agent 管理 → 其他渠道」，为接管人启用会话读取及发送权限。设备授权确认时选择目标组织。完成设备轮询、换 token、渠道许可校验及本人资料校验，才保存授权。

设备发起使用 /cli/clientId 和 /oauth2/device/code.json，scope 为 openid corpid。确认后经官方设备轮询并换取个人凭据。检查 /cli/cliAuthEnabled 与 get_current_user_profile，绑定员工 userid，另存开放钉钉号作为消息发送者 ID。轮询间隔与失效期限依据设备返回和适配器限制，服务端保存 device code 和 token。

| 工具 | 请求与验证 |
| --- | --- |
| list_all_conversations | limit、cursor。用 openConversationId、singleChat、lastMsgCreateAt 提取会话 |
| list_conversation_message_v2 | openconversation_id、time、forward=false、limit=50、mark_as_read=false。定窗口逆序读，超出上界的记录过滤，到达下界停止，核验游标单向变化 |
| send_personal_message | openConversationId、uuid、msgType=text、content 为 JSON 字符串。该 JSON 内层字段为 content |
| query_message_send_status | 发送只有 openTaskId 时查询。最多三次间隔一秒。SUCCESS 时核对 openMessageId 与原 openConversationId。FAILED 记明确失败，其余记 UNKNOWN |

Workspace 工具请求通过官方网关的 JSON-RPC tools/call。随请求传 Authorization Bearer 和 x-user-access-token，校验 JSON-RPC ID、isError 与内层 success，取业务 result。联系、会话和消息工具由适配器维护服务标识。归一化提取 openMessageId、senderOpenDingTalkId、createTime、atOpenDingTalkIds 和 messageAiSendFlag。当前真人适配器处理文本。客户端核验收发使用原会话，并核对实际发送者与回执。

### DWS CLI 云文档处理

DWS CLI 的组织账号授权与上文的应用 Stream 和个人消息接管分别配置。使用已授权组织的 CLI profile。命令参数对照本次检查的 DWS CLI 1.0.69。下面命令用于独立测试文档。

~~~sh
printf '%s\n' '# 交付样例' | dws doc +create --name '交付样例' --doc-format markdown --content - --format json
printf '%s\n' '追加的结论' | dws doc +update --node "$DWS_DOC_ID" --command append --doc-format markdown --content - --format json
dws doc +fetch --node "$DWS_DOC_ID" --scope full --format json
~~~

从 create 的 data.nodeId 设置 DWS_DOC_ID。创建与追加检查 ok、complete、data.verified 及 nodeId。fetch 检查 status=success、complete、目标文档及正文内容，确认两次写入都出现在同一文档。当前工作台以 DWS CLI 独立验证这条文档链路。要接入产品，按 DocumentAdapter 契约加钉钉执行器，保存任务、目标文档及读回结果后调用个人消息通道回原会话。工作台 Java 现有 document/capabilities 会明确报告钉钉文档适配未接入。

CLI 接入使用子进程参数数组和 stdin，校验 profile 归属，限制执行时长和输出体积。只读查询可重试。写请求结果不明时先查已存在的文档或当前版本，保留写入操作记录。

## 四、通用附件和交付控制

~~~text
resolve input origin: authorized message media / cloud link / current-session file
check authorized owner, conversation and requested operation
load bounded byte stream or read authorized cloud document
normalize file type and preserve original filename
store file reference under execution session, pass reference to model
if model emits a document candidate:
  create or update authorized target
  checkpoint artifact ID and async task ID
  read back confirmed content, attach verified provider URL to result
  verify recipient access through platform permissions or client
  enqueue reply to original authorized conversation
~~~

- 当前工作台按单条消息一个附件处理。下载前验证身份、原消息和资源标识，限制字节数。编排层上限与平台上限分别生效。录音在格式需要时转换，例如 AMR 至 PCM，转换后的文件仍绑定原会话。
- 成果文件必须属于本轮或当前工作台会话，且与执行人和租户匹配。原生上传和发送走各 BOT 适配器。真人通道将成果做成经核对的文档链接或发送文本结果。
- 给每次文档写入保留稳定的 operationId 和目标 ID，记录 requested、written、verified、delivered 等阶段。网络超时优先读回，避免重复创建和追加。读回成功以后，发送回执和接收者能打开是两项独立观察。
- 只有运行流返回真实问题或审批事件时进入等待。文档缺权限或工具失败时返回具体缺失项。完成态需有产物或明确读回结果。
