# 工程对照与配置

## 源码定位

Java 目录以现有工程模块路径保存。入口类之间的对应关系如下。

| 要实现的行为 | 源码入口 |
| --- | --- |
| 普通机器人启停、应用用户授权、绑定码和应用配置 | ImBotServiceImpl，ImBotController，AdminImBotController，ImBotInbox |
| 按员工维护接管配置、保存本人授权和绑定 | ImBotTakeoverServiceImpl，ImBotTakeoverConfig，DingTalkUserAuthorization，ImBotTakeoverController，AdminImBotTakeoverController |
| 多节点续约、连接或轮询、派发和最终发送 | ImBotRuntime，ImBotMapper.xml，ImBotMessageMapper.xml，ImBotSessionMapper.xml |
| 发现、读历史、回传与平台状态归一化 | ImBotTakeover，ImBotUserGateway，DingTalkUserMessages，ImBotGroupMentions |
| 原会话执行、问答恢复、状态更新 | ImBotExecution，ImBotInteraction，ImBotContent |
| 普通 BOT 长连接、发送和文件协议 | WecomBotChannel，FeishuBotChannel，DingTalkBotChannel，ImBotChannel |
| 云文档与 MCP 工具 | ImBotDocumentServiceImpl，ImBotDocumentAction，ImBotFeishuAuth，ImBotToolServiceImpl，ImBotWecomDocuments，ImBotMcpConfig |
| 文件识别、转换、对象存储及成果返回 | ImBotFiles，ImBotFile，File 归属与校验入口 |
| 模型调用文档和消息工具的规则 | enterprise-bot/SKILL.md、references、scripts/bot_request.py |
| 运行配置与浏览器工作流 | Node.js配置工具/server、src，配置与数据库目录的属性和线程池片段 |

Java 导出是模块源码快照，依赖原工作台的账户、租户、通用会话、模型事件、问答审批、文件存储、HTTP/MCP 客户端、统一加密与通用 RPC 设施。其他项目可以把这些依赖换成自己的身份、Agent 和文件接口。工作台原始加密工具、运行凭据及部署配置由接入环境供给。样例配置启用 servyou.work.im-bot.enabled；接入方须配置安全的统一密钥（原实现可读 SERVYOU_CRYPTO_KEY）、平台应用和个人授权。

## 接口和关键字段

业务 ID、版本和大整型在 HTTP 中统一传字符串。管理类写入携带当前 expectedConfigVersion。会话、消息和文件都在登录用户及租户范围查询。

| 路由 | 用途 |
| --- | --- |
| POST /admin/im/bot/create、/update、/enable、/disable | 保存与启停机器人。后缀接在 /admin/im/bot 后 |
| POST /admin/im/bot/user/grant、/revoke | 授权和撤销工作台帐号。群聊白名单、启停及应用功能范围从配置核对 |
| POST /im/bot/binding/create-code | 员工生成短时绑定码并发给原机器人单聊 |
| POST /admin/im/bot/takeover/profile | 按员工建立独立接管配置，关联原应用 |
| POST /admin/im/bot/takeover/update | 管理员按配置版本保存 USER 模式、本人绑定、私聊与群聊会话范围 |
| GET /im/bot/takeover/detail | 工作台员工查自己的接管状态，返回授权是否就绪 |
| POST /im/bot/takeover/oauth/start、/complete | 本人发起并完成授权。飞书提交登记回调和授权码/state。钉钉使用设备确认与版本校验 |
| POST /im/bot/document/capabilities、/execute | 查文档能力或执行选定动作。常用字段为 botKey、action、arguments、conversationFileId |
| POST /im/bot/tool/page、/execute | 查企微能力工具或执行上游工具。常用字段为 botKey、capability、tool、arguments |
| POST /im/bot/message/send | 落库待发送，按 requestId 防重。目标只能是授权会话 |
| POST /im/bot/session/page、/message/page | 按工作台权限查看会话或消息。后缀接在 /im/bot 后 |

飞书完整文档路径白名单和参数字段在 [文档动作表](../配置与数据库/文档动作表.json)。该表由当前动作枚举生成，企微固定动作部分属于兼容接口。企微 v2 以平台即时工具目录为准。请求和返回结构可直接查对应请求 VO、响应 VO、DTO 和 ImBotWebConverter。

## 数据库安装或增量更新

- 新库直接执行配置目录的 [新建四表.sql](../配置与数据库/新建四表.sql)。这份结构将接管身份、加密配置、会话水位以及人员配置关联补齐到四张新表。
- 已有四表时核对当前列及索引，按 20261116、20261117、20261118、20261119 的顺序执行实际缺失的升级。20261117 为文件与文档配置，20261118 为真人接管身份、授权和水位，20261119 为按员工拆分接管配置。升级 SQL 中包含 ALTER ADD COLUMN，需要依据现有结构跳过已执行的语句。
- 防止重复接收靠 (bot_id, inbound_key)。防止业务发送重复入队靠 (tenant_id, user_id, bot_id, request_id)。会话映射使用 (bot_id, user_id, chat_key)。按保留时间归档会话内容和文件时继续保护去重窗口。

## 独立配置工具

运行环境为 Node.js 22.12 及以上。进入参考代码的 Node.js配置工具目录，替换 server/presets.js 的三个示例应用标识，在配置页填写目标工作台 URL、路径前缀与租户。用 npm ci 安装锁定依赖并运行 npm start。本机端口默认为 18767。测试用户、组织和应用预置已换成示例。企业微信消息本人 ID 由操作者按实际授权填写，保留双 ID 校验。BOT_CONFIG_BOOTSTRAP 是进程内注入入口，可由启动环境提供已授权配置。

## Java 对照测试

测试源码包括 Java 8 单测、MyBatis Mapper 注册、真实 MySQL 及平台集成用例。运行原工程的测试时使用独立测试库，通过 im.mysql.url、im.mysql.user 和 IM_MYSQL_PASSWORD 提供连接。平台测试依赖配置和环境变量，具体输入见对应测试类。各阶段执行结果及测试范围见 [验证结果与复现步骤](../验证/验证结果与复现步骤.md)。
