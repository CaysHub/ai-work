# 跨语言消息接管实现

## 1. 运行边界与数据契约

员工在工作台绑定自己的平台账号，选择要处理的私聊和群聊，再启用接管。调度器用这份授权读原会话，模型使用工作台账号执行任务，最终由该员工的消息通道向原会话发送结果。

| 对象 | 必需字段及含义 |
| --- | --- |
| 接管配置 | tenantId、profileId、parentAppId、platform、ownerUserId、bindingUserId、messageUserId、identityMode、enabled、autoProcess、私聊及群聊开关、目标会话 ID、discoverEnabled、groupMentionName |
| 授权及版本 | encryptedCredential、expiresAt、refreshing、configVersion、generation、startedAt。configVersion 用于配置并发控制。generation 区分两次启用产生的会话和任务 |
| 运行所有权 | ownerNode、ownerVersion、leaseUntil。ownerVersion 是每次新领取递增的围栏令牌 |
| 会话 | tenantId、profileId、ownerUserId、externalChatId、P2P/GROUP、agentSessionId、generation、historyCheckpoint |
| 归一化消息 | id、sender、senderType、time（Unix 毫秒）、position（可选顺序号）、type、text、mentionedUserIds、attachmentRef、aiSent |
| 入站任务及回传 | inboundKey、requestId、providerUuid、targetSessionId、sourceTime、sourcePosition、generation、processState、sendState、providerMessageId、replyContent、fileId、expiresAt |

平台 ID 用不透明字符串贯穿 DTO、队列和日志属性。一次入站保留发言人、工作台执行人、授权员工三个身份。平台联调时从授权信息确认实际组织及员工，按租户、配置及会话限定历史和产物的可见范围。

四张工作表可直接映射至关系数据库。sw_im_bot 保留配置和租约，sw_im_bot_user 维护授权与绑定，sw_im_bot_session 持久化会话及读取水位，sw_im_bot_message 存入站任务、执行状态和发送结果。其他数据存储要提供同等唯一键、条件更新与事务语义。

## 2. 授权、配置版本与多节点

1. 管理员配置普通 BOT 并授权目标工作台员工。员工在机器人单聊提交短期绑定码，服务原子消费绑定码并保存外部身份。本人授权完成后核对绑定、平台组织和本人消息身份，然后启用 USER 配置。
2. 修改或撤销授权使用 configVersion 作 CAS。启用或切换接管时生成新的 generation 和 startedAt。入站与发送匹配原 generation。每次启用基于新时间进入处理范围。
3. 以数据库时间领取已过期或空闲的配置行。当前周期为 60 秒租约、每 15 秒续约、每 10 秒调度。只有更新一行的节点持有所有权。配置变更后关闭旧本地连接并重新加载。轮询、落库、调度、发前复查和回执写回都带 ownerNode、ownerVersion、configVersion 或当前 generation 的相应条件。
4. 飞书和钉钉用户令牌到期前 120 秒准备续期。先在有效租约下持久化 refreshing，再发一次续期请求。成功写回新 token、过期时间并清标记。请求结果未知或节点中断后遗留 refreshing，停止该配置的自动处理，由员工重新授权。消息 MCP 地址与个人 token 一样加密，界面仅取配置状态。

~~~text
claim(profile, node):
  UPDATE profiles
    SET ownerNode = node, ownerVersion = ownerVersion + 1, leaseUntil = dbNow + 60s
    WHERE id = profile AND (leaseUntil IS NULL OR leaseUntil <= dbNow)
  if affectedRows != 1: return unowned
  return loadOwner(profile, node)

writeFenced(result, fence):
  verify tenant, profile, enabled, identityMode and expected generation
  UPDATE ... WHERE ownerNode = fence.node AND ownerVersion = fence.version
             AND leaseUntil > dbNow AND configVersion = fence.configVersion
  require affectedRows == 1
~~~

锁用于守护短事务，平台请求和模型流放在事务外。最终发送事务只完成最新配置校验和抢占发送资格。员工在最后一次查历史与平台收到请求之间仍可能手动发送，应把这段竞态控制在尽量短的时间内。

## 3. 轮询、分页与持久入站

手工登记的私聊和群聊先生成会话记录。开启发现时，平台适配器按自身语义发现活跃会话。发现游标与单会话历史游标分别维护。按 ID 公平轮转目标，限制每轮处理量，避免一个长会话阻塞其他会话。

~~~text
readConversation(profile, session, fence):
  state = session.checkpoint
  if state.window is absent:
    floor = profile.startedAt - 10min
    start = max(floor, state.until - 30s) or floor
    end = now - 2s
    state.window = (start, end, cursor=null, items=[])
  if end <= start: return
  if (now - 2s) - start > 6days: pauseWithReason()
  page = adapter.history(session.externalChatId, start, end, state.cursor)
  state.items.append(page.items)
  if count(state.items) > 1000: pauseWithReason()
  if page.next:
    saveCheckpoint(state with cursor=page.next, fence)
    return
  rows = mergePreviousContextAndCompleteWindow(state.history, state.items)
  for batch of at most 50 rows:
    transaction:
      assertCurrent(fence)
      applyHumanReplyCoverage(rows)
      for row in batch:
        if eligible(row, session, profile):
          insertOnce(unique=(profile.id, inboundKey(row)), state=QUEUED)
  saveCheckpoint(until=end, history=last30(rows), clearWindow=true, fence)
~~~

分页中途退出时从上次持久化的窗口和游标继续。读完后分批落库再推进水位。如果崩溃发生在两者之间，窗口可重读，唯一键吸收重复入站。缺字段、无进展游标、平台声明结果不完整时保留水位并报错。合法空页仍可推进。

- **同条消息** 飞书和钉钉使用平台消息 ID。企微历史无可用 ID 时，按会话、实际发送人、时间、类型、正文与附件指纹生成基础键，然后在完整窗口内给真正重复的同秒消息分配稳定序号。重叠窗口用该身份合并最近 30 条历史。
- **会话与任务的唯一键** USER 会话键混入 generation 和 externalChatId。入站键使用摘要 HASH(USER, generation, externalChatId, stableMessageId)。库中唯一键落在 (bot_id, inbound_key)，避免多节点重放。
- **触发范围** 本人消息、非员工来源、可识别的 AI 发送、其他接管人的系统答复、纯空消息和启用前历史用于过滤或构建上下文。每个任务带它之前最多 30 条上下文，回复目标仍为配置所对应的原会话。

## 4. 多人群聊与人工已回复

单人接管的已选群可按配置响应。一个应用有多个接管人选择同一个群时，按被点名的员工触发。普通群消息和仅 @全体成员供上下文。飞书和钉钉各用户独立授权。企微同一 BotID 受 BOT/USER 启用互斥与授权身份限制。

1. 优先匹配非空结构化提及 ID。其次解析正文中的平台提及 ID。只有两者都没有时才匹配配置的显示名。使用明确边界、长名称优先和转义后的文字，避免相似名称、邮件地址或广播名命中。
2. 识别同一应用下其他员工的系统答复。优先匹配原会话中的平台消息回执。企微缺少回执 ID 时，可在对侧会话内按发送者、正文及时间范围核对。钉钉还可用平台的 AI 发送标志。正常人工发言仍进入历史。
3. 处理前和发送前均检查原会话。本人在输入之后有手动发言时，停止相应自动回复。企微和当前钉钉适配器对同秒无法判序的本人发言保守跳过。飞书优先比较毫秒，再比较消息位置。识别本系统已发的追问和答复，避免将它们误算为人工发言。
4. 已确认的终态回复只覆盖其绑定的输入水位。模型执行过程中到达的新输入继续排队。群在排队期间变为多人接管时，已排队的未点名任务也查最新配置。

~~~text
canReply(task):
  assertCurrentOwnerAndGeneration()
  require enabled, ownerStillBound and sameAuthorizedConversation
  if changedGroupPolicyAndNotAddressed(task): return false
  if lastAcceptedSourceTime(task.session) >= task.sourceTime: return false
  for at most 4 pages in original session over the input-to-now interval:
    if any later message is from the employee and not a known system reply:
      return false
    if page is last: return currentConfigurationStillAllows(task)
  return stopWithIncompleteHistory
~~~

从回执 ID 判断系统回复最可靠。企微按时间与正文比对属于有限的关联方式。移植时保留发送记录与依据，时间戳、来源或分页无法确认时停止自动发送。

## 5. 任务执行和发送状态

| 阶段 | 状态与转移 |
| --- | --- |
| 领取 | QUEUED → RUNNING。同一工作台会话按顺序执行，持久队列记录与责任节点分开 |
| 运行 | 模型生成文字、请求文件或调用平台工具。实际的提问或审批事件可进入 WAITING_INPUT。后续回答关联原会话。恢复已有会话使用 RECOVERING |
| 完成 | SUCCEEDED 记录结果。失败和取消分别记录 FAILED、CANCEL_REQUESTED 与 CANCELED 等进度。回复内容和发送资格单独持久化 |
| 出站 | PENDING → SENDING → ACCEPTED / FAILED / UNKNOWN。配置、权限、任务过期或已回复导致取消时记 CANCELED |

~~~text
run(task):
  if not canReply(task): cancelReply(task); return
  claimExecution(task)
  result = agent.continueSession(task.agentSessionId, task.input, task.context)
  persistOutcomeWithFence(task, result)
  if result.hasReply: markPending(task)

send(task):
  recover persisted SENDING as UNKNOWN if previous sender cannot prove outcome
  if expired or not canReply(task): finishWithoutSending(task); return
  transaction:
    verify configuration and fence again
    compareAndSet(PENDING, SENDING)
  receipt = adapter.sendAsEmployee(task.externalChatId, task.reply, task.providerUuid)
  record ACCEPTED, FAILED or UNKNOWN using the same fence
~~~

接入端持久化发送请求 UUID。飞书和钉钉把它传给平台。企微真人消息工具当前无统一回执 ID。只读失败可在预算内重试。发送超时、回执缺字段或节点在发送后退出时，保留 UNKNOWN，并回查原会话或平台任务。数据库只能约束节点的读写竞争，不能撤销平台已接受的外部操作。重启恢复时也应保留原请求 UUID 和任务上下文。

发送消息采用平台速率限制与工作池背压。查询归档时同时看 processState、sendState、目标会话和回执 ID，便可区分模型成功、平台受理和客户端送达。

## 6. 替换技术栈时的接口

~~~text
IdentityProvider.start(profile, loggedInOwner) -> authorizationUrl, version
IdentityProvider.complete(profile, callback, version) -> verifiedIdentity, encryptedCredential
MessageAdapter.discover(profile, window, cursor) -> chats, next
MessageAdapter.history(profile, chatId, window, cursor) -> normalizedMessages, next
MessageAdapter.download(profile, messageRef) -> filename, type, boundedByteStream
MessageAdapter.sendAsEmployee(profile, chatId, text, requestUuid) -> status, providerId
DocumentAdapter.run(profile, action, arguments, fileRef) -> artifactId, revision, taskId, url
Agent.continueSession(owner, session, input, context) -> events and outcome
~~~

Python 的异步 worker、Node.js 的任务队列、Go 的 goroutine 或 Java 的线程池均可实现这组接口。会话顺序、消费去重、身份校验和恢复逻辑由共享存储负责。平台细节集中在适配器，模型只选择经过授权的动作及输入参数。SQL、源码文件和配置映射见 [工程对照与配置](工程对照与配置.md)。
